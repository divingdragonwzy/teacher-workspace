# 拾题 初中英语题库

可运行的第一阶段初步产品，服务初中七至九年级英语教师。

本仓库仅保存源码、测试和使用说明，不包含本地题库、原始试卷、导出文件、账号凭据或部署项目标识。首次启动为新的本地工作空间；本文历史验收记录不代表仓库附带这些试卷数据。

源码按目录直接保存在仓库中，可查看差异、追踪版本并继续开发。仓库根目录的日期 ZIP 仅为早期备份，正常使用无需解压它。

## 功能
- 上传 .docx（最多 8 MB、每份最多 200 道题），保留原始文件和支持的配图。
- 规则拆分题目，匹配同文档内的参考答案及多段解析/范文，保存共用阅读材料。
- 支持括号前缀题号、短文编号填空、句子还原、听力选择、任务型阅读；作文要求不拆成新题。
- 图片选项标注 A/B/C/D 归属；画线文字用「【画线：…】」保留位置，方便人工核对。
- 显示答案匹配、配图、漏题/重复题号提示；从原卷重新识别时自动备份已保存草稿，已入库卷禁止重识别。
- 原文对照、修改题干和答案、设置年级/题型/多个知识点、合并误拆条目、补录漏题。
- 核对草稿可保存；明确勾选确认后入库。相同文件通过内容摘要识别，避免重复上传。
- 组合筛选与关键词检索，手动录题、编辑与删除。
- 完形、阅读等共用材料题按整道大题选择；筛选命中一个小题时仍保留整篇，分页不拆散大题。
- 组卷篮按整题计数，整体移动/移除，小题分值可单独设置；支持试卷保存与快照、试卷预览。
- 每道大题的小题、材料空号、显式题号引用从 1 开始；原题号仍保留用于来源追溯，原始题库记录不覆盖。
- 导出真实 .docx 学生试卷及教师答案；材料与共用配图每道大题只输出一次，教师答案按大题和内部小题编号对应。

## 当前边界
- 仅支持 .docx，不支持旧 .doc、PDF、OCR、音频或其他学科。
- 规则识别依赖题号和文档结构，不承诺所有试卷自动准确拆分。图片中的文字不识别。
- 复杂表格提取文字但不复刻表格布局；浮动图片、自动列表编号及复杂格式必须对照原卷。
- 答案与试题分开的两份文件暂不自动配对。未给出的答案不会生成。
- 重复题号且不能唯一对应的答案保持空白，提醒人工核对。
- 知识点是少量规则建议，可人工修改；没有调用 AI API 或产生模型调用费用。
- 初版题库上限 5000 题。尚无考试、学生、答题卡、阅卷或成绩模块。
- 当前为账号私有工作空间，没有学校/教研组共享与角色分工。
- 删除题目、删除试卷需确认，无回收站；原始上传文件保留。跨文件相似题去重未实现。

## 数据与安全
生产环境使用 D1 保存结构化数据、R2 保存原始文件与图片；不是浏览器 localStorage 演示。
每个接口按登录用户隔离数据，文件下载同样检查归属。Word 内容仅作为文本显示，不执行文档 HTML 或宏，不读取外部文件。
上传前检查 DOCX ZIP 结构及解压体积。所有数据库查询使用绑定参数。
本地开发数据与发布后的云端数据独立，不会自动复制。
试卷在点击“保存试卷”时保存；尚未保存的组卷篮在刷新后不保留，页面会提示。

## 本地启动
需要 Node.js 22.13 或以上。

```powershell
git clone https://github.com/divingdragonwzy/teacher-workspace.git
cd teacher-workspace
npm install
node scripts/local-setup.mjs
node scripts/run-framework.mjs dev --host 127.0.0.1
```

打开终端显示的本地地址。开发服务器自带仅限本机的模拟登录，不能用于公开部署。
当前电脑若 npm.cmd 出现路径错误，可直接使用 Node 调用 npm 的 npm-cli.js。

## 校验与构建
```powershell
node node_modules/typescript/bin/tsc --noEmit
node node_modules/esbuild/bin/esbuild scripts/parser.test.ts --bundle --platform=node --packages=external --format=esm --outfile=.sites-runtime/parser-test.mjs
node .sites-runtime/parser-test.mjs
node scripts/run-framework.mjs build
```

仓库中的 .openai/hosting.json 仅保留本地 DB/FILES 绑定名称，不包含原部署项目标识。云端发布需另行配置项目与认证；源码上传 GitHub 不等于上线。不要把本地模拟认证服务器暴露到公网。

## 主要文件
- `components/workspace.tsx`：教师工作台及导入、核对、组卷界面。
- `app/api/workspace/[...path]/route.ts`：上传、数据存储、文件访问接口。
- `lib/parser.ts`：DOCX 安全检查、拆题及答案匹配规则。
- `lib/question-parser.ts`：按题型拆分与答案解析、图片关联、结构质量检查。
- `lib/import-docx.ts`：统一 Word 读取流程，供首次导入和重新识别共用。
- `lib/export-docx.ts`：Word 导出与导入示例。
- `lib/question-units.ts`：整题分组、筛选、原子选入、内部编号与组卷顺序；题库/预览/导出共用。
- `db/schema.ts`、`drizzle/`：数据库结构和迁移。
- `scripts/parser.test.ts`：拆题、异常输入、答案隔离及 Word 导出测试。

### 整题选入与编号说明
- 同一来源、年级、题型且材料相同的共用材料题视为一整题。不同来源即使文章相同也不合并；没有共用材料的题独立选入。
- 数据库继续保存原题快照，展示与导出动态生成内部编号，因此已有题库无需重新上传。核对页保留原卷题号，方便对照原文；入库后按内部编号展示。
- 只重写明确的空号和题号引用，不全局替换文章中的数字；年龄、年份、金额和段落编号不随题号变化。
- 从旧试卷补齐半选大题时保留已有小题分值；若材料含有缺失的小题空号，显示提示并阻止导出，避免空号与答案错配。
- 本次 Unit1 实测：一键选入完形 10 小题，材料/题干/预览/两种 Word 均为 1–10，十个答案对应保持一致，共用配图仅保留一次。浏览器布局和 Word 内容/图片结构已验证；当前环境缺少 LibreOffice，未完成 Word 逐页渲染检查。

## 插图与导出排版更新
- 共用插图在材料中的原占位位置直接展示，题库、组卷与预览不再显示“共用材料配图／见配图”提示；相同图片每道大题只出现一次。没有占位位置的旧记录将图片放在材料末尾，缺失资源仍会提示或阻止导出。

## 是否引入 AI

本次问题来自确定性文档结构，不需要模型调用。当前没有接入 AI、申请密钥或向模型服务发送试卷。

后续建议先用 10–20 份不同来源的授权试卷建立验收集，分别统计漏题、误拆、答案错配、材料/图片错配和教师校对时间，再决定是否启用可选 AI 辅助。AI 更适合复杂非标准排版的语义分组、细粒度知识点建议以及图片文字识别；不要默认替换可追溯的原文解析。

如接入，建议采用「本地规则提取 → 结构检查 → 经用户许可，仅将异常片段发给模型 → 校验来源与题号 → 教师确认」的流程。模型结果必须保留来源和建议标记；无原卷依据的答案保持空白，不自动生成所谓标准答案。需先确定服务商、费用上限和试卷数据处理权限，再接入。

[OpenAI 官方结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)说明结构化输出可约束 JSON 格式，但内容仍可能出错；格式合规不能代替题号覆盖和人工核对。
